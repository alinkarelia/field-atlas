# Сохранность и продолжение работы · 0.3

## Полная локальная копия браузера

Откройте проект → верхняя кнопка «Копия и восстановление» → «Скачать полную локальную копию». Файл `.atlaspack` включает карточки, все локально известные оригиналы проекта, фрагменты съёмки, незавершённый обход, начало координат, планы и историю сверок. Отсутствующие на устройстве вложения карточек по известным ссылкам загружаются с сервера, если он доступен; без нужного оригинала успешная копия не создаётся. Другие серверные материалы, неизвестные этому профилю, автоматически не выбираются.

Исходные файлы включены в бинарном виде, без преобразования в уменьшенные превью и без base64. У реестра и каждого файла проверяется SHA-256. Предел текущего формата — 2 ГБ файлов, 32 МБ реестра, 512 МБ отдельного файла. Хеширование идёт по одному файлу; сам файл при проверке хеша помещается в память браузера. Крупные экспедиции следует разделять на проекты и дополнительно копировать сервер.

Для восстановления откройте копию в браузерном профиле, где этого проекта ещё нет. Сначала показывается состав, затем проверяются все файлы. Только после проверки данные записываются одной транзакцией IndexedDB. Коллизия или отказ записи отменяет всю транзакцию. Существующий проект не перезаписывается. На устройстве сохраняются прежние ID; восстановленные карточки заново ставятся в очередь. При уже существующей версии на сервере открывается сверка, а не автоматическая замена.

История конфликтов входит в копию; кеш 3D-просмотра, производные сборки и прежние задания — нет. Они доступны на сервере. Это отдельная функция от JSON-кнопки «Экспорт проекта» на карте: тот JSON содержит только реестр. В нативном приложении новый экран `.atlaspack` ещё не реализован.

## Сверка двух версий

«Передача» → «Сравнить и выбрать сведения». Для отличающихся полей выберите значение на устройстве либо на сервере. Списки людей, фотографии и план выбираются целиком как поле. Затем можно сохранить выбранное, принять серверную версию или оставить обе карточки. Перед изменением сохраняются локальная версия, текущая серверная версия, ожидавшие отправки изменения, время, способ и основание решения.

«История сверок» открывает эти сведения для чтения. Новое локальное изменение во время сверки блокирует устаревшее решение. После сохранения выбранного передайте очередь; если сервер успел измениться снова, возникает новый конфликт. Это сохраняет факт неопределённости вместо незаметной потери работы.

## Полная копия локального сервера

Из папки проекта, используя Python с зависимостями приложения:

```powershell
python -m server.backup create --data .runtime --output D:/AtlasBackups/expedition-2026-11-25.atlas-server.zip
python -m server.backup verify D:/AtlasBackups/expedition-2026-11-25.atlas-server.zip
python -m server.backup restore D:/AtlasBackups/expedition-2026-11-25.atlas-server.zip --data D:/AtlasRestored/expedition-2026-11-25
```

Пути в примере замените на свои. Папка восстановления должна ещё не существовать. Команды не перезаписывают действующую `.runtime` или копию с тем же именем. После проверки можно запустить отдельную песочницу на восстановленной папке:

```powershell
python -m server.app --port 8880 --data D:/AtlasRestored/expedition-2026-11-25
```

Создание использует SQLite backup API, поэтому сервер можно оставить запущенным. Из снимка берутся метаданные оригиналов; у частично переданного файла копируется только подтверждённый префикс. Завершённый оригинал проверяется по его исходному хешу. Включаются все таблицы, в том числе люди, связи, решения, очередь заданий, а также опубликованные файлы модели. Временная база сборки и переменные окружения с токенами не включаются.

Архив содержит реестр файлов с длиной и SHA-256. Перед публикацией копия полностью проверяется. Восстановление идёт во временную соседнюю папку: проверяются состав, пути, хеши, целостность SQLite и наличие исходников; затем папка переименовывается в указанный новый путь. Повреждение не оставляет «готовую» частичную базу. Незавершённые задания при первом запуске получают состояние, позволяющее повторить запрос.

Это локальный инструмент сохранности. Он не настраивает удалённое хранение, расписание копирования или сервер авторизации. Несинхронизированные данные браузера нужно сохранить отдельно через `.atlaspack`.

## Фоновая сборка и просмотр

Сначала передайте файлы, затем нажмите «Собрать фрагменты». Можно закрыть панель; сервер продолжает работу. Вернувшись в «Передача», вы увидите актуальный статус. «Остановить сборку» отменяет работу, сохраняя исходники. Ожидающее задание также можно отменить. После перезапуска сервера прерванную сборку нужно запустить снова; одинаковые успешно завершённые запросы не дублируют результат.

В 3D-просмотре общий обзор прорежен по всем секторам. Выберите сектор и переходите по страницам, чтобы просмотреть все производные точки; оригиналы более высокой плотности остаются отдельными файлами. Последние 12 открытых ответов доступны без сети. Ранее не открытые страницы требуют связи. Старые сборки версии 0.2 можно пересобрать новым фоновым путём, чтобы получить постраничную выдачу.
