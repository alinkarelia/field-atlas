# Полевой атлас

Рабочая локальная песочница, сервер и исходники приложения для iPhone/iPad с LiDAR. Версия разработки 0.6.1, 26 ноября 2026 года.

**Текущий код опубликован в [открытом репозитории](https://github.com/alinkarelia/field-atlas), [сборки и проверки](https://github.com/alinkarelia/field-atlas/actions/workflows/field-atlas.yml). Для iOS настроены облачная сборка Xcode, UI-тесты iPhone/iPad и выпуск неподписанного IPA; фактический результат смотрите у нужного commit SHA в Actions. Работа физического LiDAR ещё не проверена.**

В версии 0.4.2 добавлены передача оригиналов и снимка карточек в выбранное задание сайта, помощник x0 с вопросами и чтением выбранной фотографии, полевые задания с паузой, журналом восстановления и GPX, дополнительные инструменты съёмки помещения. Порядок входа и передачи, проверки и ограничения описаны в [отчёте о подключении](../Подключение-сайта-и-x0.md).

Описанные ниже серверные функции сборки и связей относятся к локальной песочнице. В рабочем подключении к archiverf.ru карточки пока сохраняются JSON-материалом; автоматическое объединение людей, сборка всех нативных секторов и автоматическая отправка полевых материалов в Drive ещё не завершены.

## Карта округа в 0.6.1

В приложение включён автономный пакет Вытегорского округа `2026-11-26.2`: дороги, населённые пункты, водоёмы, здания и 162 карточки мест и историй. Это общий набор данных с [картой сайта](https://archiverf.ru/#places/atlas/vytegra/explore). Карта открывается без входа и связи; обновление с сайта проверяет SHA-256 каждого файла до переключения пакета.

Исправлены порядок картографических слоёв относительно линий обхода, постановка точек поверх подписей и меток, начальный масштаб и доступ к поисковым результатам с открытой клавиатурой. В UI-проверку ручного контура включён поиск видимого штриха на снимке экрана, а не только подсчёт сохранённых вершин.

Тематические слои и периоды описывают содержание карточек. Это не реконструкция географии на историческую дату; у 150 карточек хронология ещё не размечена. Загрузка произвольных областей пока не реализована. Пакет OSM не гарантирует полноту тропинок или геодезическую точность объектов.

## Интерфейс съёмки и карточек

Камера открывается сразу после проверки доступности и разрешения. Во время съёмки на экране — круглые кнопки по краям; инструкции, состояние и результат открываются отдельно. Фонарик находится слева во всех режимах камеры. Внутри помещения отключена миниатюра RoomPlan; штриховка стен строится заметными полосами с сохранением проёмов, наружная сетка показывает полупрозрачные измеренные треугольники.

На карте отдельно доступны граница, дорога и тропинка. Можно записать обход по GPS или построить приблизительный контур вручную. Метки: вход, дерево, свалка, мусорный контейнер, препятствие и неподтверждённое углубление. Карточка предлагает общий вид, надпись и портрет; несколько фотографий одного вида сохраняются вместе. x0 доступен непосредственно с карты, камеры и выбранной фотографии. При необходимости для OCR создаётся отдельная JPEG-копия до 6 МБ; исходник остаётся неизменным.

Сборка 0.6.1 №18 прошла 25 модульных тестов и 14 сценариев интерфейса на каждом симуляторе iPhone/iPad. После тестов просмотрены снимки линий поверх карты, карточек и инструментов камеры. Физическая проверка LiDAR, света, камеры, GPS и RoomPlan остаётся отдельным этапом. Отсутствие тестовых режимов камеры и целостность пакета карты проверены в Release IPA. Ссылки, порядок работы и ограничения — в [отчёте сборки 18](docs/BUILD-18.md).

## Открыть и проверить браузерную песочницу

Если сервер запущен: **http://127.0.0.1:8879**. Для повторного запуска откройте PowerShell в этой папке и выполните:

```powershell
./Start-Sandbox.ps1
```

Скрипт использует Python из локального окружения или установленного Codex. При переносе: Python 3.12+, `python -m pip install -r requirements.txt`, затем `python -m server.app --port 8879`. Сервер принимает только соединения с этого компьютера. Данные находятся в `.runtime`, браузер хранит рабочую копию в IndexedDB.

1. На стартовом экране выберите **«Внутри помещения», «Здание снаружи», «Участок» или «Кладбище»**. Проекты и их карточки разделены.
2. Для плана квартиры: создайте проект «Внутри помещения» → «Карта» → **«План помещения и размеры»**. Доступны план комнаты, стена с высотами и общий этаж, выбор окна/двери, редактирование этажа, экспорт SVG. Без импорта показан явно обозначенный учебный пример. Подробнее — `docs/ROOM-PLANS.md`.
3. Для безопасного знакомства откройте **«Учебный участок»**. Все его объекты вымышленные.
4. «Карта» → «Граница», «Дорога» или «Тропинка»: используйте GPS либо точки на плане. Паузы оставляют разрывы. Незавершённый обход восстанавливается после перезагрузки.
5. «Захоронение» открывает пять шагов: место, фотографии, сведения, размеры/заметки, проверка. Можно сохранить черновик, неизвестное имя и неполную дату.
6. В учебном участке «Снять» → «Начать пример» → «Сохранить». Повторите для второй части. **Это воспроизведение синтетических измерений, а не LiDAR браузера.**
7. «Передача» → «Передать» → «Собрать фрагменты» → **«Открыть 3D-модель»**. Поверните облако точек мышью, пальцем или стрелками.
8. Для проверки связей создайте учебную карточку с человеком «Иванов Пётр Иванович», рождение `1864`, смерть `1901`. Передайте её. «Объекты» → **«Связи с архивом»** → выберите карточку → «Учебные люди». Один вариант совпадёт, у другого будут противоречащие даты. Укажите основание решения и подтвердите связь.

9. Кнопка загрузки в верхней панели → **«Копия и восстановление»**: скачайте `.atlaspack` с локальными карточками, фотографиями, сканами, историей сверок и незавершённым обходом. Восстановление проверяет хеши и выполняется атомарно в профиль, где этого проекта ещё нет.
10. При конфликте: «Передача» → **«Сравнить и выбрать сведения»**. Выберите значения полей из двух версий, укажите основание и передайте результат. «История сверок» показывает прежние версии и решение.
11. В плане комнаты откройте **«Потолок · отдельный замер»**. Можно внести контрольную высоту с источником либо импортировать контур с высотами точек. Прежние замеры сохраняются; для контура есть отдельный SVG.
12. Кнопка с четырьмя уголками в верхней панели включает **полный экран**. Съёмка занимает всю область окна, мобильные карточки открываются без внешних полей. Основные кнопки увеличены до 48 пикселей; действия остаются доступны при прокрутке формы. Подробнее — [интерфейс и полный экран](docs/INTERFACE.md).

Закрытие окна сервера не стирает материалы. Экспорт реестра на карте остаётся JSON без вложенных файлов; полная локальная копия создаётся отдельной верхней кнопкой. Серверная копия включает SQLite, оригиналы и опубликованные модели; локальные ещё не переданные материалы браузера входят только в `.atlaspack`. Команды создания, проверки и восстановления сервера — в [инструкции по сохранности](docs/RESILIENCE.md).

## Изменения 0.4.0

Облачная сборка и проверки в GitHub, отдельная иконка iOS, исправления компиляции SwiftUI. В нативном плане доступны перемещение, изменение масштаба и «Показать всё»; выбор места использует текущие координаты карты. Добавлены XCTest-проверки карточек, четырёх типов проекта, сохранения после перезапуска, поворота экрана и недоступного LiDAR. Инструкция: [сборка и артефакты GitHub](docs/GITHUB-BUILD.md).

## Исправления 0.3.2

Запоздавшие импорты не попадают в новую сессию съёмки и не заменяют уже снятые точки. При нескольких выборах фото остаётся последнее; удаление связи с фото отменяет ожидающую замену, сохраняя исходные файлы. Отказ локальной записи не открывает несохранённый проект. Повторное действие из уже закрытого окна игнорируется. Длинные названия переносятся, пустой поиск объясняет отсутствие результатов. Сценарии проверены искусственными задержками, прерванными транзакциями и потерей ответа сервера; подробности — `reports/VERIFICATION.md`.

## Что пока не является готовой функцией

- Нет подписанного установочного выпуска/TestFlight и полевых испытаний. Cloud CI запускает Xcode без локального Mac. Для установки нужна подпись, для приёмки — совместимый iPhone/iPad с LiDAR.
- В подключении к archiverf.ru реализованы вход и передача оригиналов вместе с JSON-снимком карточек в выбранное задание. Автоматическое объединение людей и графовых связей, сборка нативных секторов и автоматическая выгрузка из приложения в Google Drive ещё не завершены. Импорт людей и экспорт графа в браузерной песочнице — отдельные локальные сценарии.
- Помощник x0 подключён через сайт; предыдущие контролируемые серверные проверки описаны в [отчёте о подключении](../Подключение-сайта-и-x0.md). Сквозной запрос из этой версии приложения с физического телефона ещё не испытан. Отдельный локальный OCR-адаптер песочницы требует серверной настройки; секретов в клиенте нет.
- Сборка сейчас создаёт совмещённое **облако точек**, не текстурированную фотореалистичную сетку. Автоматический ICP/SLAM между независимыми посещениями, фотограмметрия и RTAB-Map пока не интегрированы. Для интерьеров отдельно добавлен нативный RoomPlan, но распознавание на физическом устройстве ещё не проверено.
- Географический план и AR-съёмка имеют разные системы координат. На плане покрытие показано только для заведомо привязанного учебного примера. Настоящие фрагменты доступны в своей системе до отдельной привязки по контрольным точкам.
- Нативный AR-просмотр загружает ограниченное окно предыдущих частей. Полное устойчивое покрытие большого кладбища между посещениями, подгрузка ближайших тайлов, дрейф и повторная локализация требуют реализации и испытаний на устройстве.
- Деревья и подозрительные углубления отмечаются вручную. Автораспознавание деревьев, определение скрытых могил и восстановление стёртых букв по LiDAR не реализованы и не выдаются за достоверный результат.
- Локальный сервер не предназначен для публичной эксплуатации: командные аккаунты, разграничение доступа, объектное хранилище, внешнее хранение копий и эксплуатационная инфраструктура ещё нужны. Фоновые задания и локальная проверяемая копия уже реализованы. С iPhone он напрямую недоступен, поскольку слушает только loopback компьютера.
- Нативный MapLibre использует сохранённую подложку Вытегорского округа с указанием OpenStreetMap/ODbL. Загрузка других округов и областей пока не реализована. Браузерная полевая песочница и опубликованная карта округа — отдельные интерфейсы; набор данных округа общий у сайта и iOS.

Подсказка этажа по барометру включается пользователем и требует подтверждения. Этаж можно исправить до съёмки и в сохранённом плане. В браузере работает отдельный замер потолка. Нативный код может предложить контур ARKit и позволяет выбрать точки вручную; это пока не испытанная на устройстве функция. Высота стены не подменяет замер потолка. Подробности датчиков — `docs/DEVICE-SENSORS.md`.

## Проверки

В [CI коммита bcea1b0](https://github.com/alinkarelia/field-atlas/actions/runs/45872373768) пройдены **384 проверки песочницы**: 47 JavaScript, 73 Python, 31 общий браузерный сценарий, 88 проверок интерфейса, 29 проверок планов помещений, 18 проверок сохранности/сборки, 72 проверки полноэкранного интерфейса и 26 проверок сбоев/задержек. Включены перезапуск, офлайн-карточки, прерванная передача, несовпадающий хеш, конфликты версий, ложные совпадения людей, разрывы трека и просмотр 3D. Клавиатура и безопасные отступы здесь смоделированы в браузере. В том же прогоне прошли 26 проверок FieldCore, а на каждом симуляторе — 25 модульных и 14 UI-тестов. Их нельзя считать испытанием физических датчиков. `reports/VERIFICATION.md` сохраняет описание предыдущих прогонов.

```powershell
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/browser.cjs
node tests/ui-audit.cjs
node tests/room-plan-browser.cjs
node tests/resilience-browser.cjs
node tests/fullscreen-ui.cjs
node tests/edge-ui.cjs
```

Для браузерного теста нужны Playwright и Chromium. В текущей среде они берутся из Codex; переменные `FIELD_RUNTIME`, `FIELD_PYTHON`, `FIELD_PLAYWRIGHT_MODULE` и `FIELD_CHROME` позволяют задать другие пути. Тест запускает отдельный временный сервер, не затрагивая рабочую `.runtime`.

## Сборка iOS на Mac

```sh
swift test --package-path ios/FieldCore
brew install xcodegen
cd ios
xcodegen generate
xcodebuild -project FieldAtlas.xcodeproj -scheme FieldAtlas -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Для установки на устройство откройте проект в Xcode и настройте свою команду подписания. Симулятор проверяет сборку и интерфейс, но не заменяет LiDAR-испытание. Результат компиляции и UI-тестов привязан к конкретному commit SHA в GitHub Actions.

## Состав

- `web/` — интерфейс песочницы, офлайн-хранилище, просмотр модели.
- `server/` — локальное API, SQLite, приём файлов, геометрия, x0, связи.
- `ios/FieldAtlas/` — нативные экраны и адаптеры устройства.
- `ios/FieldCore/` — общие модели и геометрия, 26 Swift-тестов геометрии, форматов, потолка, подсказок этажа и перемещения карты.
- `tests/`, `reports/` — воспроизводимые проверки и снимки интерфейса.
- `docs/` — схема данных, интеграция сайта, границы текущей реализации.

Исследование готовых решений и начальная спецификация находятся рядом с проектом: `../cemetery-tools.md`, `../cemetery-research.md`, `../field-app-blueprint.md`. Текущий фактический статус определяет этот README и отчёт испытаний.
